# Security Reports

[简体中文](SECURITY.md) | [English](SECURITY.en.md)

Do not include API keys, tokens, passwords, private recordings, or chat databases in public issues.

Once maintainers enable GitHub private vulnerability reporting, use the repository's Security page. If it is not enabled, request a secure contact channel in an issue without vulnerability details. No security email has been announced; do not guess an address.

Revoke and regenerate exposed credentials; deleting a file does not undo exposure. This project provides no hosted backend and promises no security-response deadline. Public deployments require your own HTTPS, authentication, rate limits, redacted logs, and maintenance.
